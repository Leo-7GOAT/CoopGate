# 新恢复基线接入性能门控前的一致性验证

V34 完整开发表明，含执行器状态的恢复能完成原强滞后基线的十个中止条件，但会付出部分通行成本。要把该恢复基线接入 MARL 性能门控，必须先解决预测与执行是否指向同一个控制器的问题。直接沿用旧基线的价值预测，再在执行末端改变动作，不具有原来的相对性能解释。

本轮先验证完整恢复预测器，不修改正式风险校准、V32 网格或原有统计标准。当前不新增训练、不声称获得新风险证书，也不将本轮诊断的真实未来信息传入在线控制器。

## 基线价值必须对应实际的恢复规则

扩展状态包括当前运动状态、上一条实际命令、全局决策时刻，以及两个含义不同的量：

- 用于参考动力学预测的执行器状态点估计。
- 由实际命令历史与参数范围得到的执行器状态区间，用于物理恢复认证。

即使参考状态点已知，也必须保留完整的区间。预测器每一步先按 V34 的规则求名义规划提案、检查新停车条件，必要时执行同一制动备份。随后更新参考动力学和命令历史区间。候选动作只替换第一步；此后执行完整的相同恢复基线，直到原 25 s 截止或任务完成。

对于该完整反馈基线 B，门控所需的量是同一扩展状态下的

\[
\Delta_i(z,u)=Q_{B,i}(z,u)-V_{B,i}(z).
\]

Q 的后续策略、V 的后续策略和真实回退必须一致。逐车成本、登记到达时间及插值到达时间也保持原定义。任何不完整的参考分支都不能提供性能准入证据。这个一致性条件是后续公平对照的基础，不是新的策略改进定理。

## 两类完整检查

1. 对 V34 已完成的全部 15,032 个真实决策状态，核对编译基线核与原 Python 控制器的命令、恢复标志和名义规划失败身份。该项使用各决策处已经记录的运动状态和命令历史区间。
2. 对全部 640 条实际 SUMO 轨迹，从初始状态做一次不间断的完整预测。只为该离线诊断提供真实逐车参数和实现过的外生创新；预测内部不插入中间观测状态、真实后续命令或观测执行器校正。比较完整命令序列、物理状态、执行器状态、观察区间、到达事件、成本及失败信息。

这两类检查分开计数。第一类逐状态一致不能替代第二类完整闭环预测。640 条来源轨迹包括五场景、四类执行器和全部旧失败条件，共享 160 个旧初态。本轮没有新的 SUMO 执行或独立效果样本。

完整预测需要分别传播实际参考状态点和区间内存。基线规划异常可能导致备份执行，这种情况下记录的规划转换数仅包含成功返回的调用，另设完整性标志；不能把它当作包含异常内部工作的总计算量。完整调用的墙钟耗时仍应在真实部署比较中单独测量。

数值比较要求命令和恢复身份完全一致，连续量误差不超过 1e-8；有限覆盖不构成任意浮点输入、资源故障或编译器的形式化证明。若某条件不匹配，保留全部输出和错误，完整检查不宣告通过。

## 随后的对照约束

验证通过之后，学习门控、物理切换适配器和基线才能在同一执行器类别信息、同一观察区间、同一停车判据、同一初态及外生扰动上比较。现有 MPS/MAMPS 是明确标注的共享判据适配器，不能称为原论文优化器及保证的原样复现。性能风险仍需针对实际部署的完整策略进行独立校准；旧基线上的证书不能直接迁移。

在线性能预测只能使用预先声明的参考参数和固定扰动路径。这里用于查错的真实参数、真实未来扰动属于离线信息，不能用于声称实际部署中的门控收益或风险保证。

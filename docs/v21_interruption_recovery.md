# V21 中断记录与追加恢复

2026-10-21 核查时，原两组研究的 Python/SUMO 进程均已不存在，临时日志目录与监督进程退出凭据也不在原位置。无法确定中断原因，不能补写原进程成功退出，也不能把文档此前的“运行中”当作当前状态。

只检查调度标识、记录数量与文件完整性，尚未分析这两组部分数据的收益、采用或风险。到达时序研究保存了 6,573 条结果记录，原定 6,656 条，缺 83 条；其中分片 1、2 有完整文件凭据。匹配动力学迁移研究保存了 10,073 条结果记录，原定 12,160 条，缺 2,087 条。后者另有一条仅保存轨迹的边界执行，因此轨迹文件数为 10,074，不能把它直接算作已提交结果。

## 恢复规则

新工具 `tools/recover_interrupted_v21.py` 为本次中断单独建立证据。原 V21 控制器、仿真环境、训练模型、调度、初态、分析函数和统计规则全部保持冻结；原始分片不修改。恢复目录为 `artifacts/v21/interrupted_recovery_20261021`。

1. 冻结所有原文件的 SHA-256、逐分片压缩备份、精确缺失后缀与回放清单。只接受原调度的连续前缀；额外轨迹只允许出现在紧接前缀的边界位置。
2. 在补跑之前，对每个控制器和每种动力学的首个已有案例，以及每个分片的首末案例执行实际 SUMO 回放。这些选择不依赖成败或收益。除实际计算耗时外，结果、完整轨迹、决策及错误信息均须完全一致。
3. 仅补跑原冻结调度的缺失后缀。已有结果保留原数值和计时；新结果写入独立目录，每个案例单独落盘。边界孤立轨迹若能解析，须与重新执行的完整轨迹逐项一致。异常或比较失败的实际输出先落盘，再停止后续阶段。
4. 新监督进程保留其创建的真实进程句柄，只有本阶段全部工作进程成功退出后才进入下一阶段。新日志存入项目目录，原进程的退出状态一直记录为未知。
5. 对全部原始和恢复记录进行原冻结的完整独立复核、全调度核对及统计汇总。时序研究的冻结复核函数通过单独的只读文件视图读取完整轨迹；不改写旧目录。迁移研究使用既有轨迹加载接口。恢复后的报告另存，并记录每条轨迹的来源和计时阶段。

恢复回放不增加独立初态数；同一案例重跑也不增加效果样本。混合采集阶段的耗时不能解释为独占部署速度。所有失败均保留，新研究不继承 V19 风险证书。

## 与后续校准的关系

原 `prepare_prospective_validation_v21.py` 要求原监督进程成功退出，当前不满足。不能伪造退出凭据使该入口通过。后续需要单独的恢复完成验证入口，核对本次冻结清单、全部回放、恢复进程真实退出、完整独立复核以及逐条来源，之后才调用原先已经冻结的完整模型组选择函数。模型组、阈值、风险预算、校准和最终样本量均保持原规则。

冻结清单已确认：18 次时序研究回放、27 次迁移研究回放，合计 45 次实际 SUMO 一致性检查；通过后才补跑 83 + 2,087 条缺失记录。6 个原始分片的压缩备份均已生成并通过压缩文件完整性检查。

`tools/select_recovered_v21.py` 已实现独立的恢复完成验证入口，要求真实监督进程退出凭据、三个完整执行阶段、两个完整独立复核和逐条来源一致。它调用原完整模型组选择函数，仍不能凭恢复成功直接启动校准。恢复实现的 10 项测试及该入口的 7 项测试通过；实际回放、补跑及完整结果仍须分别验证。尚无新的风险认证或最终效果结论。

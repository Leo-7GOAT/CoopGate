# 状态载入后的原生子步时钟校验

完整加载实现仍在首个设置的重放中失败；原输出保留于 dmps_sumo_reload_development。
额外诊断显示：载入 .6 秒快照后连续五次无参数 simulationStep，原生时钟仍为 .6，
但 Python 闭环已经累计 .5 秒。随后调用才开始前进，导致扰动索引和执行器记忆与
实际 SUMO 子步不同步。这个差异不能通过只核对载入瞬间的位置和速度发现。

新增连接包装器把无参数 simulationStep 改为明确的“当前原生时钟加一个 .1 秒子步”
目标，每次立即断言实际原生时钟确实达到该目标。调用者显式指定的目标时间原样传递。
该修正只作用于新增诊断环境，不修改 SUMO 安装、冻结环境、物理递推或学习/门控算法。
原完整加载、控制模式恢复以及相同浮点容差保持不变。三个接口检查覆盖回退后的时钟、
未推进时拒绝、显式目标透传。

提交新增源码、驱动、测试和协议后，在全新 dmps_sumo_clock_development 目录执行
原八个固定输入、每个最多 12 步的诊断。之前所有失败和原生 XML 均保留。不以多次
工程尝试增加独立样本量，继续不声称训练完成、公平信息比较或风险证书。

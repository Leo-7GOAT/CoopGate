# V19：保持门控行为的计算优化

冻结实现为 `deduplicated_planner_v19.py` 和 `cached_portfolio_v19.py`。原规划器、原门控及正在运行的大样本协议保持不变。该优化不增加新的学习能力或新的风险证书。

## 两项优化及等价依据

第一项在一次联合规划调用中跳过已评估的相同命令。状态、上一命令、时钟以及规则续轨都固定；最优值只会下降。对于已完整评估的命令，其目标值已与当时最优值比较过；对于提前截断的命令，已累计成本是完整成本的下界，而且已经足以拒绝。它们在以后更小的最优值面前都不能变成严格改进。候选顺序、两轮坐标搜索、1e-10 比较容差和物理投影保持一致。名义代价累加只包含非负的时间与命令变化项，因而支持原有下界截断。

第二项在一次门控调用内复用完全相同状态上的基线命令。键包含三个车辆的位置、速度、上一命令以及离散时钟；配置在该调用内固定。每个键保存同一确定性规划器的输出。扰动序列仍逐步实际传播，完整尾轨仍重新累计；复用的是同状态下的基线动作。缓存没有量化，不跨门控周期保存，也没有删除执行记忆或时钟。

因此，在原配置和数值比较有效的范围内，可以按候选处理次序及尾轨时间步归纳，得到相同的规划动作、预测状态和成本，再得到相同的门控选择。实现保持 float64、关闭 fastmath。单元测试专门检验一个浮点 ULP 的状态改变、不同上一命令和不同时钟都不会误用同一缓存。

该论证解释为何可以减少工作；有限测试不能穷举全部状态。下面用独立保留的原实现作为对照，核对实际执行。当前统计认证尚未完成，优化实现也没有额外的风险认证结论。

## 成对实际 SUMO 回放

冻结 29 个案例，每例分别运行原实现和缓存实现，共 **58 次 SUMO**。案例包括两个代表初态、四种扰动、三个固定模型，补充所有六个非空采用审计案例及唯一逐车退化案例。选择用于机制验证，属于事后回放，不增加独立统计样本数。

所有 **667 个配对决策步**的命令、状态、候选检验记录、组合选择、17 场景差、采用标志，以及最终逐车时间/命令变化量均完全相同。原有退化被保留，没有通过改变门控行为获得计时优势。

| 指标 | 原实现 | 缓存实现 |
|---|---:|---:|
| 控制计算时间之和 | 104.687 s | 78.453 s |
| 内部预测步数 | 4,890,482 | 3,788,486 |
| p50 | 14.48 ms | 14.98 ms |
| p95 | 966.18 ms | 701.51 ms |
| p99 | 2408.74 ms | 1730.04 ms |
| 最大值 | 5646.90 ms | 3635.66 ms |
| 超过 500 ms 的决策步 | 61/667 | 53/667 |

总控制时间降低 **25.06%**，内部预测工作量减少 **22.53%**。缓存对便宜决策引入少量开销，主要降低昂贵决策的时间。全部函数预热后计时，案例中交替执行原实现/缓存实现，以减少顺序偏差；其他冻结实验同时运行，因此这是有并发负载的成对计时，不是空闲机器上的实时性验收。该批案例也不同于先前 32 初态的总体性能实验，不能把 966 ms 与旧报告的 745 ms 直接视作算法退化。

**500 ms 周期目标仍未满足**，最大耗时仍有数秒。后续需要继续降低长尾并进行独立、明确机器负载下的计时。不能只报告 25% 加速，就声称已经完成实时部署。

# 正式公平对照启动前的失败记账修正

本修正在任何 V41 正式执行前提出，依据代码与合成反例，不读取运行中实验的效果。
V39 科学计划、V41 绑定及全部旧源码保留原样。新入口为
`tools/execute_fair_failure_v44.py`；旧 V41 正式入口不再用于主比较。

## 反例与修正

旧分析要求所有零采用回合与基线完全相同，包括失败身份。因此，一个首次采用之前
中止且成本封顶为 25 的回合，会被拒收而无法进入完整汇总。现在只对双方成功的
零采用回合要求轨迹成本相等；真实失败保留全部原始成本、采用标记和失败类别。
零采用失败不进入采用后风险分母，但单列其数量并阻止该方法进入主排名。

旧分析还能在基线失败、候选成功且成本较小时产生可入选方法。现在基线失败的配对
保留，伤害保守置真，并标记相对改善不可评估。所有百分比成本数值仍计算且保留，
但不能解释为相对有效安全基准的收益证明；任一基线失败使主比较没有合格参照。

主排名新增明确工程条件：方法本身及其全部配对基线均无观测失败。原有 usefulness
条件、风险/采用/收益误差分配与排名顺序不变。条件满足时正常数据的原有数值结果
逐字段一致。零观测失败不是总体零失败概率证明，也不提供新的安全证书。

这里的失败继续包含原协议定义的计算超时：即使退回基线后任务完成，只要证据包
超过截止仍记为超时失败。超时数单独报告，不能因严格规则可能导致无人合格而删除、
放宽截止或事后更换失败定义。碰撞、未完成、中止、约束违反分别记数，允许类别重叠。

## 保持的比较范围

八种方法、640 个 IID 初态、5120 次执行、160 个块、方法次序、三个模型及全部
控制器/候选/预测/500 ms 截止/历史校准字节均不改。新计划完整包含旧计划，再增加
分析修正、旧计划与绑定 hash、修正源码 hash；不是第二批独立样本。旧正式目录若
已有运行证据或原生进程，修正冻结与执行均拒绝。

新监督器在私有全局映射中重用旧监督器的 worker/watch/summarize 代码对象，替换
输出路径、绑定校验与最终分析，保留原收集器和独立物理重放。没有修改模块全局。
启动时沿用项目隔离检查；所有块齐全、原生零退出、证据链完整并全量重放后才能分析。

命令顺序：提交源码 → `freeze` → 提交计划 → `bind` → 提交绑定 → `watch` →
终态 `summarize`。冻结与绑定不启动仿真。仍优先完成已有实验和原统计尝试。

这项修正解决失败样本的分析完整性，不把机制适配器变成原论文复现。历史校准
701/711/721 映射到当前策略仍是迁移适配器，不继承证书；固定路径 advantage LCB
仍不具有原 CSPI 的因果推断保证。公平对照结果只支持所声明适配器及信息条件。

## 验证边界

合成反例用于检查失败处理，不是实际算法性能。真实 SUMO 开发检查使用独立开发
种子 139885001（原策略）及 139885002（人工注入提案异常），各执行完整八方法并
持久化、重放。异常由所有方法共享的证据生成器触发，因此包括 always-baseline；
不能写成原策略或传统基线在真实使用中观察到八次失败。这些回合不进入正式样本。
开发时将计时阈值放宽以隔离数学与失败重放；不验证正式 500 ms 吞吐或实时性能。

新增重放期间终态文件被改写的拒绝检查单独通过，共 27 项。正常数据与旧汇总器
已有字段逐项一致；故障注入八回合全部零采用、封顶成本 25，并进入失败计数。

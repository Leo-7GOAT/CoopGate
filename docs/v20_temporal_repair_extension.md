# 时变扰动开发集上的动作调整配对扩展

16 初态研究验证了实现一致性，也暴露了新增退化与较大计算开销。为判断这些现象在更大开发集上是否稳定，本扩展在既有 128 个时变扰动开发初态上补跑三份冻结完整调整控制器。协议在读取该 128 初态研究结果前冻结；已完成的 16 初态研究属于开发依据。

## 配对范围与统计单位

新增运行数为 `128 × 4 × 3 = 1,536`，与原研究的 6,656 次运行合并形成 8,192 条不同控制器运行记录。两部分共用初态 63100001–63100128、相同场景抽样规则、扰动流及预先固定的实际模式选择流；独立初态仍为 128 个，新增独立初态数为零。

原研究保留基线与三个模型的原 17 路径、交替 33 路径、采样 33 路径、合并 49 路径门控。本扩展只补充相同三个模型的完整采样 33 路径动作调整策略，不重复执行已有基线，也不复制旧结果冒充新运行。此前 16 初态范围 63200001–63200016 与本次配对集不相交。

学习权重、候选动作权重 `[1, 0.75, 0.5, 0.25]`、物理过滤器、全部 33 条预测路径、排序、准入阈值与故障处理均保持此前冻结版本。所有模型结果都保留，不根据任何一个模型表现选择训练种子。

## 完成条件与独立复算

每条新增轨迹都保存并检查物理约束、实际采用动作、完整预测检查数及失败记录。程序在两个新增原生工作进程和原研究原生监督进程均退出成功后，才读取完整原研究结果进行合并。监督程序持有原进程的 Windows 内核句柄，防止 PID 复用；观察超时不触发重启。

合并要求初态定义、模型、共同源代码、随机模式选择和统计规则完全一致，且完整运行网格没有缺失、重复或方法重叠。原门控的每个已采用情形必须仍被扩展策略采用；这项采用包含检查与实际收益、逐车退化分别报告。

最终复算逐状态重建所有新增候选集合，重算每个不同已采用动作的 33 条预测路径，并从完整记录独立重算所有方法的采用数、退化数、完成数和平均收益。候选与预测复算复用先前独立审计的基础函数，不调用性能选择器或候选扩展函数。完整调整策略与原采样门控的增量收益按初态配对重采样；不把模式或模型当成额外独立样本。

## 解释边界

这是开发集配对扩展，不是风险校准或独立最终确认。它不能继承 V19 某个固定策略的证书，也不能因零观察退化声称 5% 风险认证。计时来自不同采集阶段的并发桌面负载，不构成严格配对的计算速度实验；完整耗时和超过 500 ms 的次数仍须报告。

冻结协议为 [`temporal_repair_extension/protocol.json`](../artifacts/v20/temporal_repair_extension/protocol.json)。开发集完成后，需要依据全部模型的收益、采用率、逐车风险和计算代价确定下一步；最终候选仍须使用另行冻结的新校准与确认数据。

# 用独立原生进程隔离快照恢复

显式子步目标修正之后，较晚快照的嵌套分支比较通过，但回载初始快照时即发现原生
位置和速度与保存值不符。试验性发送过去的目标时间也未修复，所有失败与诊断保留。
因此不将原进程快速或完整 reload 当作本场景已验证的分支克隆。

新增 ProcessConnection 在加载快照时只关闭本环境拥有的 SUMO 连接，并使用相同
配置与该快照启动一个全新原生 SUMO 进程。保留显式子步目标、控制模式恢复、全部
Python 状态/RNG 恢复及原验证容差。不会重启任何研究 Python 进程或其他 SUMO 实例。
这可能很慢；本阶段不主张工程可部署性，只建立可信的接口参照。

提交新增实现、驱动、测试和协议后，在全新 dmps_sumo_process_development 执行原
八个固定输入、每个最多 12 步的完整接口诊断。其种子、模型、原 MCTS 参数、固定
提案和失败规则与首版协议一致。若失败，仍保留前缀并停止，不改变范围使其通过。
该接口仍是特权模拟器规划、零 critic、零训练步，不能用来宣称 DMPS 性能或新风险
保证。之前的多次工程尝试不增加独立统计样本量。

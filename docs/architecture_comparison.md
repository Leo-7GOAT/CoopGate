# 端到端 分层架构与置信门控的区别

本页比较架构职责，不比较未经实验的性能。CoopGate 当前没有完成与视觉端到端、PPO→A*→MPC 分层系统的统一任务对照，因此不声称优于这两类架构。

## 三种不同的设计问题

| 设计 | 主要回答 | 典型数据流 | 主要接口 |
| --- | --- | --- | --- |
| 端到端驾驶 | 从观测如何直接学出驾驶输出？ | 图像或状态 → 学习网络 → 轨迹或控制 | 网络输入、学习目标与驾驶输出 |
| 分层规控 | 决策、规划和控制如何分工？ | 行为决策 → 路径或轨迹规划 → 跟踪控制 | 行为、参考轨迹、执行命令 |
| CoopGate 的门控 | 当前学习候选是否值得且允许执行？ | 学习候选与传统基线 → 同状态预测检查 → 选择执行指令 | 相对收益、许可条件、回退命令 |

这三个维度可以组合。端到端网络也可有安全过滤器；分层控制链也可在决策层或控制层设置门控。**门控不是分层架构的反义词，也不天然优于端到端。**

“端到端”也不等于强化学习：其训练方式可以是模仿学习或强化学习等。“分层规控”不自动等于层次强化学习：PPO 决策加 A* 规划和 MPC 跟踪属于模块分层，只有多层策略等也由学习框架组织时，才需要进一步讨论 HRL 的定义。

## 本项目实际实现了什么

训练使用三个独立局部 actor 和训练期集中式 critic，联合 on-policy 轨迹、GAE 和 PPO 更新。部署时 critic 不参与候选评分；共享门控仍集中执行，所以整个控制系统不是完全分散式。

当前任务输入是三辆车的结构化状态，输出是固定路线上的联合纵向加速度。它不包含视觉感知到转向的完整链路，也不是 PPO→A*→MPC 的复现。传统基线是有限联合候选规划加可恢复停车检查，不能把它统一称为通用 MPC。

一次控制回调执行以下工作：

1. 计算传统基线并维护实际已执行命令的记忆。
2. 从三个 actor 的动作偏好构造联合候选，保留原候选并增加至多四个局部次优修复请求。
3. 在候选搜索内部检查物理可恢复性、逐车相对性能、越界相位和观测历史预测。拒绝一个候选后继续检查其余候选。
4. 存在许可候选时执行选中指令，否则执行同状态下的传统基线。

候选分数是固定有限预测路径中的最坏相对团队收益，当前门槛为 0.25%。**它不是“该动作有多少概率安全”的置信概率。**有限预测与条件物理检查也不等于真实未来的完整不确定性覆盖。

## 如何区分收益来源

本轮验证的是门控后的完整闭环。相同候选池的名义控制器去掉置信与历史过滤；随机弃权对照再按校准数据估计的概率决定是否运行名义控制器，用于区分筛选与单纯降低采用率。

弃权概率使用校准样本中目标与名义控制的采用数之比，在该经验分布上匹配期望采用率；它不保证确认集或总体采用率相等，也没有证明统计等价。对照表中的收益与退化数是描述性证据。

三角色参数更新和实际控制贡献支持“真实 MAPPO”的实现事实，不能单独证明集中式 critic 相对 IPPO 的因果优势。新候选搜索的独立开发比较同时改动持续搜索与局部次优扩展，未单独识别二者各自贡献。MPS/MAMPS 对照为共享物理检查的原始提案适配器，不是完整论文复现，也未匹配扩展候选池。

完整数值、统计假设及原始凭据见[当前实验报告](mappo_top_two_attempt6_completed_20261104.md)。

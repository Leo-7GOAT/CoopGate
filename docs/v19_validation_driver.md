# V19 冻结实验的连续执行

`tools/advance_validation_v19.ps1` 接续当前已运行的四个校准分片。监督进程不会重启已有工作、替换策略、查看校准中间结果或改变阈值。它持有原进程的句柄，避免仅凭 PID 判断进程身份；仓库内的互斥锁防止重复启动。

四个进程全部正常结束、各自完整记录存在后，流程依次执行已经冻结的命令：完整汇总校准、计算统计认证与对照选择器、提交校准记录、生成并提交独立确认启动记录、启动四个独立确认分片。后续依次完成最终比较、实际整轨迹部署回放和独立报告复算，保留负面认证结果及全部训练模型。

归档提交只包含该阶段指定目录，开始前要求暂存区为空。现有输出、冻结源代码变化、异常进程退出、缺失完成记录或统计／回放检查失败，都会停止推进并保存错误日志；不会覆盖先前结果，也不会自动重跑失败样本。GitHub 推送失败会被明确记录为待发布，本地已提交的预注册与独立实验仍可继续，不执行强制推送。

这是当前实验各阶段的依赖流程，不是新的风险认证或额外样本来源。流程走完也不自动宣称研究目标完成：仍须逐项审阅真实风险、收益、采用率、公平对照与适用范围。

## 已执行的验证

在四个真实校准进程仍运行时，`-CheckOnly` 已验证所有冻结源代码和计划，未创建日志目录、提交或最终测试进程。另使用三个实际短生命周期 Python 进程验证：正常退出且有完整记录会通过；正常退出但缺失完整记录会拒绝；即使存在完整记录，非零退出仍会拒绝。没有重启任何进程，也没有使用仿真或校准结果。

本地检查记录见 [`validation_driver_checks/checks.json`](../artifacts/v19/validation_driver_checks/checks.json)。测试可用 `tests/test_validation_driver_v19.ps1` 在 Windows 重新执行，它只使用独立临时目录。

## 运行与检查

启动参数必须是当时真实校准进程的 PID，按分片 0、1、2、3 排序，并使用新的日志目录。加 `-CheckOnly` 可先只读验证；正式执行前脚本本身必须已提交且未修改。加 `-Publish` 才会执行已授权的 GitHub 推送。

启动后不要手动并行执行相同的校准、最终启动或归档阶段。每个阶段的输出、四个最终工作进程的标准输出／错误，以及阶段事件都保存在指定日志目录。进度判断以实际进程或工具会话为准；`state.json` 和锁文件单独存在不代表仍在运行。

如果监督进程结束，应先检查退出状态、日志和实际子进程，再决定恢复方式。观察超时不表示实验已经停止，停止监督进程也不等于已停止它创建的工作进程。当前版本遇到部分完成的旧阶段会拒绝再次启动，要求先审阅已有证据。

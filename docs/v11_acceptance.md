# V11 验收结论与历史问题复查

本轮得到明显的指令平顺性改善，但没有达到全部预先声明的性能目标。200个全新初态、四类误差、九种方法，共7200次SUMO执行；正式协议、算法和阈值均保留原样。

## 十项标准实际通过九项

相对V10，在600个扰动条件下，平均到达代价由9.716667 s降至9.621667 s，减少0.095 s，即0.9777015%。冻结标准要求至少1%，所以该项**未通过**。其余九项通过。不能把0.9777%四舍五入为1%后改判，也没有用补跑或重新挑选场景改变这一结论。

累计指令变化量由34.432617降至19.732292 m/s²，减少42.6930%；平均指令变化率由1.004687降至0.583773 m/s³，减少41.8950%。这些是指令层指标。到达时间与总变化量的97.5%配对整簇bootstrap区间分别为[0.062778,0.129448] s和[13.434889,15.980024] m/s²，均排除零。样本为200个独立初态簇，不能把三种扰动当成独立初态扩增样本量。

完整方法800回合全部完成，无记录碰撞、合同违规、中止或超时；暖机控制计算周期P95为8.3443 ms，首响应P95为24.6875 ms。安全与实时性声明仍受模型与计时条件限制。相对V10，113个初态簇到达时间更好、41个持平、46个更差；总变化量分别为193、4、3个，均保留在数据中。

## 复现检查与性能验收分别报告

`verify_release_v11.py` 核验源码和文件哈希、全部回合、统计重算、指标恒等式及SUMO轨迹复跑。数据可以正确复现，同时某项性能目标未达到。CI通过表示前者通过，不将9/10改为10/10。

加上 `--require-acceptance` 会要求十项标准全部通过。对于这一公开版本，该命令应返回非零退出码并报告时间改善目标未满足。这个行为用于保留真实验收结果。

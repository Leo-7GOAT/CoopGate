# 扩展失配原计划执行：共享桌面资源说明

已核对冻结执行器：`watch` / `worker` 没有项目静默前置条件，控制器没有墙钟
决策截止；`perf_counter` 只记录诊断耗时。感知陈旧和命令延迟由仿真时钟/决策
索引定义。正式运行可以与本项目独立进程并行，不需要改动原执行器或重新绑定算法。

启动前已验证原计划与执行绑定：192个独立初态、九个因子单元、每单元十三方法，
合计1,728个区组、22,464次真实SUMO执行。计划、110项执行依赖、模型和运行时
哈希匹配；原execution和blocks目录均不存在，没有读取该正式研究的部分效果。

当时本项目三个旧校准采集进程和课程训练进程存活。只记录这些已知归属的进程
身份，不把它称为完整系统负载测量。原worker仍用单Torch线程，使用独立SUMO
连接与同步物理步进；不改变方法次序、模型、阈值、种子、失败定义或统计分析。
执行仍由原监督器核对原生身份、退出状态、完整区组和文件哈希后才允许汇总。

因此本次耗时仅作共享桌面条件下的诊断，不能用于独立部署延迟、最坏执行时间
或相同算力性能的主张。这个安排不适用于V44含500ms墙钟截止的公平比较，
也不绕过V42要求前序统计尝试完成的前置条件。所有执行与审计源码均保持冻结。

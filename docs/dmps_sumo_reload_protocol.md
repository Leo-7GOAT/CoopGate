# 原生初态快照的完整加载修正

v2 审计在同一首个初态上发现实质重放不一致：快速载入 t=.1 的车辆插入后快照，
随后五个子步时钟到 .6，但车辆里程、位置和速度均未改变。原首次推进车辆 0 行驶
6.966639079 m。较晚的 t=.6 快照载入后推进到 1.1 的重放一致。
两个失败版本及额外原生 XML 诊断全部保留，这不是改变容差或挑选案例的理由。

[SUMO 官方保存/加载文档](https://sumo.dlr.de/docs/Simulation/SaveAndLoad.html)
给出完整 traci.load 和快速 simulation.loadState 两种方式，同时说明部分内部模型
状态不保存。不能将仿真器 API 名称当作完整闭环状态已经恢复的证据。

新增 DMPSReloadEnv 使用原网络/路线/步长/种子/碰撞策略，附加 --load-state 和
--begin 快照时钟进行完整加载。明确保存并恢复每辆车的 speedMode/laneChangeMode；
这些外部控制参数不能依赖快照 XML 默认行为。原执行每个子步都会设置目标速度，
因此无额外持续速度计划需要用于下一子步。本环境无背景交通、换道或运输实体，
本接入结论不能推广到任意 SUMO 环境。

此为更慢但需验证的加载实现，不报告为提速。原快照、原作者 MCTS、控制映射、统计
身份保持不变。提交本新增实现、驱动、协议及两个接口检查之后，在全新目录
dmps_sumo_reload_development 重跑同样八个固定 12 步前缀，不重抽种子，不修改浮点
容差或失败判据。保留特权动力学/未来扰动、零 critic、无训练、无性能结论的边界。

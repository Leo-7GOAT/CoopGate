# 名义规划的零分候选快捷检查

本实验仅优化预测里的名义规划投影，不修改动作族、评分、停车证书、门控阈值、扰动
路径或训练模型。比较对象为当前冻结实验使用的 V37 MemoizedRecoveryGate；不叠加
上一轮证书复用，单独衡量这项改动。正式风险、公平对照、机制消融和失配实现保持原样。

## 为什么可以在完整排序前检查一个顶点

原投影枚举三车各自 backup/hold/proposed 的 27 个笛卡尔积顶点。评分是逐维平方差
之和，按原 mode 索引稳定排序，依次检查证书。有限 proposed 总能提供零分顶点；
平方分数非负，因此第一个零分顶点就是稳定排序后的第一项。

每一维在原选择顺序中寻找第一个实际 float64 平方差等于零的选项，按三进制拼接
索引，即得到原稳定排序的首个零分顶点。若其通过同一证书，则无需构造和排序其余
顶点；若失败，完整执行原枚举和稳定排序，只跳过刚刚检查过的相同顶点。
非有限 proposed 保留原完整路径。没有使用近似距离或新的容差。

这里不能简单先检查 proposed：hold 与 proposed 的非零微小差值可能平方下溢为零，
原稳定排序会优先选 hold；有符号零和相等 backup 也影响返回的精确命令字节与索引。
实现检查的是实际平方分数，并保留这些并列规则。正的浮点平方分数相加不会变成零，
所以逐维首个零分选项与联合首个零分顶点一致。结构论证假定原纯证书正常求值，
不把资源耗尽等外部运行异常作为算术等价性保证。

名义 tail、coordinate rollout、提案缓存、恢复选择及预测内核的原函数体逐段保持
相同；只有模块内的投影/规划依赖绑定改变，使用独立文件和编译缓存，fastmath=False。
原逻辑工作计数不改。不会把代码复制或计算捷径本身说成新的科研理论。

## 开发验证与固定运行范围

先检查：函数体 AST 一致、稳定排序的完整证书访问顺序、相等/有符号零/下溢/非有限
输入、256 个固定连续随机投影输入、四类动力学与首末扰动路径的全部 22 个预测输出
和输入字节、规划缓存统计、首步及恢复失败。测试不是新的风险证书。

提交源码、测试、驱动和协议后，固定执行三个模型、四类动力学、两种规则的 24 个
实现配对，每个配对两轮，每轮两个实现，共 **96 次真实 SUMO 回合**。开发种子
139891001，nominal 场景，clean 创新。每个配对第二轮与第一轮的实现顺序相反，
不再让规则与实现先后顺序绑定。固定预热不计时；不按结果换种子或挑配对。

每个回合先持久化再独立物理与完整门控重放。四个执行的全部原非计时字段必须一致，
包括既有提案缓存统计；否则保存前缀并停止。全部完成才报告时延，保留每轮和合并
结果。只有一个开发初态跨设置复用，既不是 96 个独立场景，也不作时延显著性或硬
实时声明。若实际提升仍小，如实保留，不修改正式截止或牺牲证书来获得加速。

# Windows 文件占用导致的检查点中断

2026 年 10 月 19 日，恢复分片 2 在将已刷新到磁盘的临时文件替换为 `episodes.json` 时，因 Windows `WinError 5` 退出。监督进程正确拒绝继续后续阶段，其他三个进程继续执行。进度观察器此前直接读取运行中的大记录文件，可能与 Windows 的替换操作冲突；读取方式和替换缺少重试均属于基础设施问题。

正式文件含 10,034 条完整记录，临时文件含 10,035 条。两者都符合冻结执行顺序；临时文件的前 10,034 条与正式文件逐字节相同，已有轨迹集合与临时文件一致。新增的已完成案例是初态索引 1002、pulse 扰动、portfolio0_1812。此处仅检查执行身份和记录完整性，未计算部分风险或据此选择样本。

新的独立恢复目录保存替换前的正式文件、完整临时文件、轨迹、异常日志、冻结计划和源代码。提交后，先保留原始计时及所有结果，原样提升临时文件，再使用先前已冻结的恢复执行器重放最后一个案例。全部非计时指标和物理检查通过后，只执行剩余 205 个原计划案例。

新代码仅替换检查点写入：针对访问拒绝和共享冲突，每 0.25 秒重试，最多 41 次；其他错误直接返回，超过重试预算时保留正式文件和临时文件。模拟器、策略、模型、顺序、统计规则均不变。今后的运行进度从小型状态文件和真实进程句柄读取，不再反复打开活动中的大记录文件。

此次额外边界回放单独计数，不增加独立风险样本数。第一次恢复中该分片已经完成并保存到正式或临时文件的 728 次运行全部保留，第二次恢复仅新增 205 个原计划案例。第一次失败的进程记录保持原样，不能伪装成正常完成。

静态证据：`artifacts/v19/checkpoint_recovery_20261019/`。这是一次基础设施恢复，不改变风险证书的适用范围或完成条件。

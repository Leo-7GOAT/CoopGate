# 独立校准与最终确认的完整执行协议

当前入口为 `tools/execute_prospective_v23.py`。沿用已冻结的完整模型组选择、统计规则、初态区间、四种扰动和三个模型，不修改门控或既有科学源码。当前开发选择为 phase05。新数据只能在旧初态的完整集成成功、原生进程成功退出、部署与离线选择完全一致、独立协议提交后开始。

首版 v21 入口在启动监督进程之前遇到 Windows 进程列表的中文编码错误，没有生成新的 SUMO 执行。原协议、源码和错误日志保留，原观察进程退出码未知，没有补写为成功。v22 仅将进程查询的 PowerShell 输出和 Python 解码统一为显式 UTF-8；无法解码或不完整的进程身份会拒绝执行，不会被当作没有活动进程。新增测试覆盖中文路径和失败时拒绝继续。它不是新的门控算法或统计尝试。

v22 完成全部九十条采集，但监督程序将 Windows 虚拟环境启动器 PID 与实际 Python PID 直接比较，导致复核尚未开始便退出，实际退出码为 1。完整封存数据和失败证据保留。v23 增加原生进程身份握手：子进程等待，父进程通过系统查询确认启动器、原生进程与父子关系，再允许子进程开始工作；原生 PID 用于数据凭据，启动器句柄用于真实退出码。该接口已用实际 Windows Python 子进程验证。新的九十次集成仍使用同一个旧初态，旧九十条另行计入集成计算开销，新增独立样本仍为零。冻结前还要求运行源码、Git 对象和快照逐字节一致，防止换行转换破坏跨机器指纹。

## 执行预算与独立单位

| 阶段 | 初态 | 主执行 | 观测初态预测 | 独立部署回放 | SUMO 总执行 |
|---|---:|---:|---:|---:|---:|
| 集成，旧初态 63100001 | 新增 0 | 40 | 10 | 40 | 90 |
| 校准，63500001–63504096 | 4,096 | 163,840 | 40,960 | 0 | 204,800 |
| 最终确认，63600001–63601024 | 1,024 | 40,960 | 10,240 | 40,960 | 92,160 |

正式两阶段合计 296,960 次实际执行，其中 204,800 次是原预定主执行。预测与部署回放不会增加独立样本数。每个独立初态包含四种扰动以及相同的十个完整控制器：基线、三个原始学习、三个名义门控、三个 phase05。三份模型始终作为完整组保留。初始化只读取当前观测状态，另外登记；它不构成一条完成的控制轨迹。

## 选择发生在真实结果之前

每个初态先将位置、速度传给只接受观测状态的预测接口。接口使用固定内部种子和无扰动模型运行十条完整预测，将每条轨迹立即提交数据库。此时没有该初态的主执行结果。

在最终确认和集成阶段，接口随后用已固定的校准结果选择六种适配方法、三个模型对应的十八个完整策略。预测、选择、选择时间、校准指纹和策略别名在主执行之前保存。校准采集阶段不从自己的结果生成选择。集成使用显式标注的人工配置，仅测试连线，不生成风险结论。

随后运行四种扰动下的全部十个主执行控制器。最终确认另经部署分发器执行四十条独立回放。原始学习、名义门控与选定门控三类固定适配器已覆盖九个候选，基线也固定执行。多个适配方法选中同一个完整控制器时共享这条部署回放，别名全部登记；不拼接车辆或动作。每个初态核验 18 × 4 = 72 个方法/模型/扰动映射。

完整命令序列、物理状态和非计时结果必须与单独主执行一致。部署选择仅依赖观测预测与固定校准，不因哪个主执行结果更好而改变。

## 持久化、失败与完整复核

每个初态使用独立 SQLite 块。结果和完整轨迹在同一事务中写入，写入发生在核验之前，失败记录不会因断言而丢失。块只有覆盖精确角色顺序后才能封存。已存在的块不能被覆盖或重新采集。

采集和独立复核由不同进程完成。独立复核重建每条主执行的物理轨迹、原始 actor、基线、名义准入、候选集合，以及已准入动作的完整扰动预测；另外检查观测预测与真实无扰动运行一致、部署命令与主执行一致。每初态清理数值缓存，不改变预测集合或样本单位。

控制器产生的未完成、中止、碰撞或约束事件保留为实际失败。仿真初始化或基础设施异常停止该阶段，保留已提交前缀。中断恢复需要另立冻结恢复协议，保留原退出证据与未知状态，只补缺失后缀并执行事先确定的边界复核；不得重置统计尝试次数、增加初态或反复运行直到通过。

监督进程读取真实子进程退出码；外层观察进程记录监督进程的实际退出码。日志文件、状态文本或观察超时都不能代替成功退出。分析必须同时取得完整采集、完整复核、全部原生退出和全部块指纹。与本项目无关的其他 Python 工作不构成停止条件。

## 分析与对照范围

校准调用原 `calibrate_observations`，不更改 4,096 初态、实际模式随机流、IUT 整组检验、0.025 首次尝试预算或对照选择规则。LTT、conformal 和均值策略改进适配使用同一主执行数据与九个候选，不替换未通过的主要风险主张。它们仍是具有不同保证目标的既有方法适配，不声称完整复现原论文的全部算法。

最终确认必须读取提交后固定的校准文件。即使主要风险主张没有通过，最终确认仍按预定方案完成并保留失败结论。三模型分别满足实际采用率至少 20%、成本改善至少 0.5%、配对均值区间下界为正，并且主要整组风险主张通过，才满足原登记的主要验收。全部执行是否完成另外完整报告，不以额外筛选改变注册的统计条件。

分析逐项核对实际部署选择与离线评估选择。Conformal 的完整预测准备时间单列，包含模拟器初始化和全部十条预测；不把该费用转嫁给无需预测的固定适配器。保留所有控制器和初始化计时、选择耗时及每初态完整墙钟时间。当前方法没有实时性结论。

## 执行顺序

1. 提交执行器和测试，`freeze preflight`，提交集成协议。
2. `watch preflight preflight`，等待真实进程完成，再 `analyze preflight preflight`；保留完整九十条记录与证明。
3. 提交成功集成证据，`freeze prospective`，提交完整正式协议。此步之前不能生成预留新初态。
4. `watch prospective calibration`，全量完成并复核后执行 `analyze prospective calibration`，提交固定校准结果。
5. `watch prospective confirmation`，全量完成并复核后执行 `analyze prospective confirmation`，保留所有方法、模型及失败结果。

每个命令均通过同一个入口执行，运行目录为仓库根目录，使用项目 Python 环境。冻结命令和数据目录均拒绝覆盖。协议的冻结与集成测试通过不等于科学目标达成。

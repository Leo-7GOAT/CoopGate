# 封存案例键的容器格式兼容：正式执行前固定的新增入口

真实 `episode_store_v21.observations` 将 JSON 案例键读出为 tuple；冻结的完整因子
汇总、联合风险 finalize 和 CSPI 导出三处却将其直接与 list 比较。在 Python 中
同内容的 tuple/list 不相等，因此这三处会误拒绝完整正确的数据。真实封存库
单元夹具可复现该错误；它不是物理或统计失败，也不能靠删除样本解决。

原冻结源码、采集程序和计划全部保留不改。新增入口用原函数相同的 code object、
defaults 和 closure，配一个私有 globals 副本，仅把 observations 依赖替换为
“调用原封存读取器，再将键容器转成 list”。键的每个值、顺序、body、trace 不变。
不修改任何导入模块的全局变量，不跳过任何原有退出、安静运行、哈希、完整覆盖、
物理重放或统计检查。原始反序计划、错误 metadata 和改动数据库仍然拒绝。

独立合同在三项受影响的正式采集尚未开始时冻结，绑定新增入口/测试/本文档、
原三个消费者、统计入口、底层封存读取器及三份原计划。V42 尚未建立执行绑定；
将来按原 bind 规则也会包含新增工具源码。其原先前置实验必须完成的要求不变。
这个合同不是重置试验、变更指标、替换模型、修改风险阈值或读取中途效果。

后续使用顺序如下，仍须先满足各原程序的全部前置条件：

1. 冻结仿真环境运行 `tools/finalize_episode_keys.py factorial`，执行原完整 3,200 次
   因子实验的全量汇总，成功后增加兼容执行身份及原报告/回放/核验哈希。
2. 提交原汇总与兼容身份后，同环境运行 `tools/finalize_episode_keys.py cspi-export`。
   原出口仍要求所有回合完整和原全量审计，只改变读取键容器。另存出口兼容身份，
   绑定原数据完整回执，不改数据字节或原导出回执。
3. 提交导出及其兼容身份后，用独立 baseline Python 运行
   `tools/finalize_episode_keys.py cspi-analysis --source <原作者源文件>`。此步先核对
   兼容出口身份，然后在原单线程上下文中调用不改动的统计流程，不转换统计数据。
4. 联合风险两阶段全部完成并满足原安静运行要求后，冻结仿真环境运行
   `tools/finalize_episode_keys.py joint-risk`，调用原全量回放与推断。

兼容身份在每个原消费者成功返回后独占写盘，绑定本合同、原源码及原输出哈希。
不得直接调用三处有键格式错误的旧 CLI 然后把拒绝解释成科学结果。旧函数仍可
用于审计源码身份；正式执行采用上述已披露的新增入口。

这项修复只是容器表示接入，不形成效能提升、新风险保证或方法创新。正式数据
尚未采集，不能用检查通过替代后续完整实验。

# 复合延迟与状态区间下的制动恢复：独立开发组件

本组件尚未接入车辆闭环或任何冻结实验。它补齐的是“什么状态集合下，存在一条
已检查的制动序列”这一物理前提，不宣称提高任务完成率、学习收益或风险验收结果。
制动不等于到达目标。所用区间传播、备份轨迹与终端不变集属于标准控制工具，
不能将这些构造本身写成首创。

## 输入与模型

当前三车状态盒 X、执行器记忆盒 M、已经执行的指令前缀以及待检查指令 u 是
唯一在线输入。公共范围沿用时间戳估计器：增益 g∈[0.78,1.22]、阻力
c∈[0.0001,0.001]、惯性 τ∈[0.12,1.25]、FIFO 延迟 d∈{1,2,3} 个
决策周期、创新 w∈[-0.1,0.1]。物理步长 h=0.1 s，每指令保持五个物理步。
不读取真实参数、真实记忆、未来扰动或仿真器。状态盒与记忆盒必须实际包含真值，
时间戳和已执行指令记录必须可信。

每车的真实更新为

\[
 m^+=r m+(1-r)u_{k-d},\quad r=e^{-h/\tau},
\]
\[
 v^+=\operatorname{clip}_{[0,20]}(v+h(gm^+-cv^2+w)),\qquad p^+=p+hv^+.
\]

对每个将来的决策，把所有可能的历史/FIFO 输出取区间并。候选指令之后，按
每决策最多下降 2.5 m/s² 的幅度逐步降至 -5 m/s²。记忆更新是 r、m、输入上的
多仿射式，其盒端点给出外包络；非负速度上的平方阻力单调，增益乘记忆按符号
取端点。盒传播放松了固定参数及固定延迟造成的相关性，可以保守拒绝可行方案。

## 有限检查与永久制动条件

每个物理步检查整个盒间仿射轨迹的固定路线几何约束：同支路保持前后距离；
异支路冲突区的可能占用时间不重叠，并在双方进入合流接近区域后保持间距。
几何计算使用更严格的正间距余量和扩大的闭冲突区，范围仍只是原三车路线模型。
它不是任意二维交通环境的碰撞证明。

达到以下终端条件才接受：

\[
 \bar v_i=0,\qquad \bar m_i<-\rho/g_{\min},\qquad
 \max Q_i<-\rho/g_{\min},\qquad u_{\rm hold,i}<-\rho/g_{\min},
\]

其中 ρ=0.1；Q 包括所有**未来仍能从 FIFO 流出的指令**，不能只检查当前制动
指令。前缀不足以排空初始队列时还必须包括虚拟零指令。实现另保留严格数值余量。
零速不是“速度足够小”：只有速度更新在裁剪前的整个上界严格为负，才利用裁剪
得到精确的零速集合；其余情形保留速度区间。

**条件命题。** 在实数运算、输入盒包含真值、公开动力学范围正确、指令精确执行
以及原固定路线仿射步间运动合同成立时，若有限轨迹通过且满足终端条件，执行返回
序列并永久保持末指令，不会违反所检查的路线合同。

证明由两步组成。首先，逐步区间包含性使每个真实状态和执行器记忆落在检查盒中，
因此盒几何检查蕴含真实轨迹的路线约束。其次，终端后所有可能延迟输入与记忆均
不高于 -ρ/g_min，凸组合记忆继续保持该界；由于增益为正且 g≥g_min，在 v=0 时
有 gm+w≤0，裁剪保持 v=0，位置不再变化。队列排空后永久末指令保持相同性质。
这不依赖对未来创新采样，也不依赖某个有限扰动库恰好覆盖未来。

## 必须保留已验证的备份后缀

若候选 u 获得证书，执行一周期后，原证书的剩余序列仍是一条可用备份。
下一次规划不能仅因为重新估计的盒更宽、搜索超时或新候选未通过就删除该序列。
可以采用新证书覆盖旧计划；否则必须继续执行已有后缀，到终端后保持末指令。
`RetainedBrakePlan` 实现了独立的序列保留机制：新候选通过才替换，拒绝时保留旧
后缀，后缀耗尽后永久输出末指令。指令发出后必须确认才能再次规划；确认值不一致
会使证书状态失效，重复取指令不推进时钟，调用者修改返回值不改变已存序列。
该管理器尚未接入 SUMO。调用者必须在**确实执行一个完整决策周期之后**确认，
并核对实际执行器输入、时钟和物理步数；软件确认本身不是物理执行证据。检查
已覆盖拒绝后逐项保留、终端保持、替换、复制隔离、错误确认失效，不据此宣称
解决了原有闭环中止或实机故障恢复。

若没有初始证书，本有限制动族未通过并不能证明状态不可恢复、碰撞不可避免，
也不授权把中止仿真当成安全停车。可能需要不同恢复策略或更小初始可恢复域；
不能通过删除失败初态来声称原任务已解决。

## 数值与研究边界

实现使用 float64、传播外扩和几何余量，未采用经验证的定向舍入区间运算。
因此条件命题不是程序在全部浮点输入上的机器证明。失败可能来自盒相关性丢失、
有限制动族、有限搜索长度或真实不可行；返回原因不能混用为不可避免碰撞结论。
默认最多 64 个决策的检查长度是开发实现上限，不是 25 s 任务完成认证或实时预算。

检查包括：独立真实动力学的延迟/参数角点与随机轨迹包含、终端后的最坏正创新、
遗留正指令队列反例、区间冲突而中点安全的反例、原路线几何实现的独立对照及
非法输入/指令限制。没有新的 SUMO 执行，没有读取正式采集中间效果，没有学习
训练或独立总体风险样本。冻结的 117 次闭环失败记录以及现有正式协议保持。

## 完整已封存前缀诊断的预定范围

在生成诊断输出之前，固定分析最新已退出并完整审计的 117 条原生轨迹的全部
2,245 个接收前缀，包括全部 39 个中止观测。每个前缀独立重算公共状态估计，
检查当时最强合法制动指令及同一后续制动族，最多 64 个决策；不挑选通过的子集。
全部三种预处理、三个旧初态和十三种原方法身份保留。计算不读取真实参数、状态、
执行器记忆或未来创新。会报告全部九个格子的初态通过数、帧通过数和中止帧通过数，
以及全部逐帧结果；在看到输出后不修改此实现与判据。

该结果仅回答“在旧轨迹的公共前缀处，本充分检查能否找到制动序列”，不执行该
序列，不证明新闭环成功、实际停车或任务进步，也不新增独立初态。初始拒绝不能
变成删除困难初态的依据。它不替代仍在运行的正式校准、OOD 或公平对照。
入口为 [完整开发域诊断](../tools/audit_compound_backup_domain.py)。

# 与已有多智能体物理门控的共同条件对照

本次补充使用[MAMPS原论文](https://arxiv.org/html/1910.12639v2)算法1的模式搜索结构，以及论文讨论的整系统MPS回退。它们回答物理可恢复性问题，不能要求原方法自动具备本项目研究的逐车相对性能风险保证。

仓库早期`shield.py`中的近似几何实现不作为本轮对照：该实现使用不同的车辆接口和预测条件。本轮适配器直接使用当前固定三份学习模型、同一强协同规控基线、相同观测、动作限制与原有区间制动证书。明确称为`mamps_shared`和`mps_shared`，不称原论文机器人环境的完整复现。

## 算法对应与修改

MAMPS模式搜索从三车全部采用学习动作开始。若联合候选未通过安全检查，将被标为不可恢复的车辆改用基线，重新检查整个组合；若模式没有变化则尝试全基线。模式在一次调用内只从学习变为基线，下一周期重新开始。MPS适配器只比较全学习和全基线。两者均不添加逐车性能准入，也不按实验收益调整搜索。

原论文的恢复控制器和确定性可恢复性检查被共同条件接口替换：候选混合使用强协同规划器的当前动作；可恢复性判断仍使用本项目全部车辆逐渐制动并到达停止集合的区间证书。这是显式适配，不能直接移用原论文的安全定理或计算开销。

为给模式搜索提供逐车标记，将现有几何约束中每个失败的车辆对标记给双方。所有标记保持到联合停止集合，不能在某一辆车提前停止后清除其约束。三个标记的合取与旧的全局区间证书相同：动作合法性、每个物理子步的约束和共同终端条件均保留。最终执行前还调用原全局证书复核。

在共同证书有效、基线动作可认证的状态中，单调模式搜索有限步终止，并返回通过同一物理条件的动作。这只涉及既定模型下的物理可恢复性，不保证相对初态全程基线的成本或到达时间不退化。强惯性失配超出误差假设时仍保留失败。

## 冻结的比较范围

沿用已完成的全部开发和动力学迁移案例，不读取进行中的风险校准结果：

- 开发：128个旧初态、四种扰动、三个固定模型、两种新增方法，共3,072次执行。
- 迁移：五类场景各32个旧初态、四种动力学、三个固定模型、两种方法，共3,840次执行。
- 完整对照合计6,912次新执行，独立有效性初态新增零。
- 先用开发第0个初态及各迁移场景第0个初态做完整接口集成，共144次；集成验证全部完成并取得真实成功退出后，才启动完整网格。

两个方法交替先后顺序。完整轨迹和未完成/中止结果先存入事务数据库，再复核；每个初态的24次执行构成一个不可覆盖的块。物理轨迹由既有独立审计器重建，实际动作再从相同状态重新计算。

比较指标包含团队成本、每车成本和到达时间、任务完成、物理误差越界、实际采用及采用后退化。采用要求实际命令在至少一辆尚未到达车辆上偏离同状态的共享基线，不能仅因模式标签为学习就计入。任何车辆成本/时间高于配对基线，或本方法执行失败，均记为退化；基线本身失败也单独报告。

最终报告同时保留已有全部控制器的结果；主体直接比较两个新增物理门控与phase05，迁移表另包含原始学习和名义性能门控。开发按原先预定的随机流选择实际扰动模式，保留四模式组合计数；不把四种扰动当作四个独立样本。迁移按32个初态配对，不跨场景混成一个风险证书。

这是已知开发/迁移网格上的方法补充，置信区间仅作描述性配对分析，不作为新的独立最终确认或统计认证。新对照与旧控制器复用同一初态和外生噪声；旧耗时来自不同执行时段，不能据此宣称配对实时加速。正在运行的正式风险校准和缓冲实现复测保持冻结。

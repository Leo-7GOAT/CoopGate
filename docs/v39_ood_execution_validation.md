# V39 OOD 执行器的真实 SUMO 联调

本记录对应正式 OOD 计划冻结前的工程验证，不属于 192 初态、22,464 次运行的效果数据，也不参与策略选择、风险校准或阈值调整。

`tests/test_ood_sumo_integration_v39.py` 使用独立开发种子 139880001 和 139880002。前一组检查三种观测条件下各四个决策周期的固定命令；后一组检查三种观测条件下完整恢复基线回合及独立重放。未加载学习 actor，未使用正式实验初态。

验证覆盖：

- SUMO 初态放置和实际读回；
- 每车命令 FIFO 延迟、加速度滞后、增益、二次阻力及共同创新序列；
- 各物理子步的速度与位置更新；
- 无噪、有偏抖动和陈旧/丢帧三类观测，确认门控收到的输入与观测记录一致；
- 完整回合的控制器重放、成本与失败记账，以及回退命令一致性；
- 损坏观测哈希，以及重新计算哈希后篡改观测，均被独立核验拒绝。

首次真实回合测试暴露了浮点边界问题：SUMO 读回的初态与设定值存在舍入差，核验器根据解析浮点状态重建的观测哈希不能与实际输入字节一致。修复后，独立物理/观测重算以声明数值容差比对，观测哈希仍对实际记录字节精确验证，控制器则在已验证的实际观测上重放。没有取消物理检查，也没有将观测哈希检查改成近似匹配。

运行命令（PowerShell）：

```powershell
$env:COOPGATE_RUN_SUMO_SMOKE='1'
python -m pytest tests/test_ood_sumo_integration_v39.py -q
```

普通测试默认跳过这六项，以免在执行冻结计时实验时意外启动仿真进程。六项通过只说明这组工程检查通过；不证明学习策略有收益，也不证明失配条件下基线或门控安全。

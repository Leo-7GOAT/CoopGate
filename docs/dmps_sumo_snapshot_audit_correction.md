# SUMO 快照审计的整数类型修正

首轮提交 b96254bc 对应输出 dmps_sumo_snapshot_development，在首个设置的嵌套恢复
比较阶段因 TypeError 停止。比较器把 PCG64 的 128 位整数状态传给 numpy.isclose，
触发 object 类型不支持 isfinite；这不是已判定的物理轨迹不一致。
原源码、失败文件与计划均保留，不覆盖输出，也不报告完成八个前缀。

新增 v2 审计驱动只替换递归比较器：整数和布尔值严格按原类型精确比较，浮点仍为
绝对容差 1e-8、相对容差 0；新增错误路径定位。没有调整仿真器、快照接口、原规划器、
种子、动作、恢复尾段或原实验范围。三个针对性检查包含 128 位整数低位变化拒绝。

修正源码和测试提交后，在全新目录 dmps_sumo_snapshot_development_v2 重跑原八个
固定开发前缀。此为工程故障后的显式重跑，不是重抽场景或新增独立样本。
原协议的特权模拟器信息、零 critic、无训练、无性能结论限制全部保持。

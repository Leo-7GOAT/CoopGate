# CSPI 交通回合接入：零支持候选的实测边界

按提交 `904ccc9d` 的固定开发协议执行，进程退出码为 0。160 个旧初态各选一种动力学，
三个模型共享分配与拆分，没有新增 SUMO 执行或独立样本。拟合/调优/安全测试/评估
分别为 64/32/32/32 个初态。四项数据隔离与失败处理检查通过。

**本次没有获得可用于论文主比较的 CSPI 性能结果。** 三个模型都在原作者选择函数
之前被预设的零方差检查判为不可检验，保留原因并回退基线。不能把这六个回退输出的
零采用、零收益写成 CSPI 被 CoopGate 击败，也不能将“不可检验”写成通过风险认证。

## 原因与原函数诊断

训练组评分的最高分位数阈值，在调优组没有选中任何回合，因此该阈值相对始终使用
基线的 DR 影响分数恒为零、协方差对角为零。

| 模型 | 五个候选在调优组的覆盖数 | 最高阈值 | 最高候选在安全测试组的覆盖数 |
|---|---|---:|---:|
| 1802 | 26, 22, 13, 5, 0 | 1.877698 | 4 |
| 1812 | 25, 22, 12, 5, 0 | 1.882794 | 4 |
| 1822 | 26, 22, 12, 5, 0 | 1.852852 | 4 |

这不是原阈值端点问题：独立的指示函数差估计与原 PDE 在全部调优/安全测试候选上
一致。这里也不能把训练评分的第九十分位数当作新场景有 10% 覆盖概率的保证；结果
模型在小训练集上拟合，训练评分与外部评分分布并不必然相同。

随后进行了明确标记的事后诊断：对完全相同的随机日志、阈值和 RNG 种子直接调用
未修改的作者选择与测试函数，没有替换原接入结果。原函数在三个模型上均产生
`invalid value encountered in divide` 警告；四种选择输出均指向调优组零支持的
最高阈值。相应原 CSPI 与 CSPI-MT 安全测试全部未通过。这是在本开发输入上的
实际行为，不能据此推断原论文连续大样本实验失效。

## 公平对照接入的实际要求

1. 完整回合是处理单位。把闭环控制步当成 IID 日志会夸大样本量，当前实现不这样做。
2. 原函数只能接收随机分配分支的实际奖励，另一分支成本保留在独立事后审计文件。
3. 评分、候选阈值、调优、安全测试、最终评估必须明确区分；辅助模型只由拟合组训练。
4. 正式候选支持处理规则必须在新测试数据前固定。仅调优数据驱动的候选筛选可以成为
   披露的接入改动；不能检查安全测试收益后删掉不利候选，也不能默默给零方差添加噪声。
5. 任何支持率或样本量设计必须有外部覆盖依据，不能将训练分位数直接当作真实概率。

因此后续正式比较仍需要足量独立随机日志、预先规定的支持与退化处理，以及匹配的
训练和评估预算。本次保留了这个接入失败，防止在正式比较中把一个数值退化的原方法
作为弱基线。当前原计划和正式统计验收未修改，未为获得通过而重抽数据或另选阈值。

另外两种完整控制器在相同 32 个评估条件上的描述性结果保存在原始文件中。由于整个
V36 数据的总体结果此前已被查看，这个划分不是新的盲测，不能用于宣称泛化改善。
CSPI 面向期望策略价值；采用后逐车损害概率和物理安全仍需要项目自己的单独检验。
